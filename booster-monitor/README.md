# 增效剂蓝图捡漏监控

这是一个支持本机运行及 GitHub Actions 的宁静服公开合同监控器，当前监控八种超强增效剂蓝图：蓝色药丸、撞击感、疯癫、坠落感、思维冲击、梦呓、X—本能、游离感。

默认从官方星域目录读取所有星域的公开合同，包含高安、低安和 00 交货。各星域列表分别读取全部分页，再跨星域轮流核验新合同；某星域读取失败时会显示覆盖不完整，并保留旧核验记录。只接受包含同一种目标蓝图拷贝的物品交换合同，核验拷贝标志、剩余流程数、数量、价格和到期时间，并显示 ME/TE。制造成本采用基础用量，未应用 ME/TE 或建筑加成；材料在吉他按足量卖单采购，成品按伏尔戈星域最近七天每日均价加权估算。求购合同、拍卖、混装包、原图、流程数缺失、失效合同和超过设定产量占比的机会会被排除。

利润是估算值，不是保证收益或完整实际净利润。公式为：成品参考收入 − 销售费用预留 − 蓝图合同总价 − 气体及原材料采购成本 − 额外费用预留。默认销售费预留 5%，额外费用每 50 流程预留 1000 万 ISK，须按自己的安装费、设施服务燃料、运输和改价成本调整。一次性反应配方购置费未单独估值。默认每 50 流程最低利润 1 亿、最低回报率 20%，每张至少 50 流程，单批产量不超过区域一周成交量的 25%，允许所有地点交货。所有门槛均可在网页中调整。

邮件方向固定为 **LadyGuaGua 发信 → MikeChong 收信**。程序不能创建/接受合同，也不会自动付款或下单。邮件授权使用 EVE SSO 的 PKCE 流程，只申请 `esi-mail.send_mail.v1`；刷新令牌在 Windows DPAPI 加密文件中保存，网页和日志不会显示它。授权时必须选择 LadyGuaGua，收件人会由 ESI 解析并检查不能与发信人相同。

## 使用

1. 本版本取消自动启动器，不含 PowerShell、批处理、隐藏进程启动或自动安装依赖的脚本。保留杀毒软件对旧 `start.ps1` 的隔离，不要恢复它，也不需要添加白名单。旧脚本已被删除，本次无法复核其完整内容，不能将查杀结论直接认定为误报。
2. 安装 Python 3.11 或更新版本后，在解压后的 `booster-monitor` 文件夹打开终端，手动执行 `python -m pip install -r requirements.txt` 安装依赖，再执行 `python app.py`。自行打开 `http://localhost:8787/`，运行期间保留终端窗口；在终端按 Ctrl+C 或点击网页“退出程序”结束运行。关闭网页本身不停止扫描。
3. 本机独立发信模式需要 EVE 应用 Client ID。注册时回调地址填 `http://localhost:8787/oauth/callback`，权限选择 `esi-mail.send_mail.v1`。在网页中填写 Client ID 并保存。不要把 Client Secret 或刷新令牌粘贴到这里。
4. 点击“授权 LadyGuaGua”，在官方登录页选择该角色；成功后本机邮件开关自动打开。可以先暂停扫描、发一封测试邮件，确认 MikeChong 收到，再继续扫描。

程序每批最多核验 160 个尚未检查过的合同，批次结束后等待 30 秒；首次可能需要很多批次，页面展示已核验进度，不能将未扫描的合同视为没有机会。ESI 合同列表约缓存 30 分钟，实际新合同发现速度受缓存影响；程序遵守响应的 Expires、ETag、Last-Modified 和限流头，不会通过更换参数绕过缓存。网络、429、503 或分页更新时间不一致时会退避。

体积预筛来自 ESI 的实际蓝图体积，以及当前成交量、产量占比和最低流程数推导出的最大张数；缺失物品体积时不套用这个预筛。记录里的“失效/待复核”不能作为当前机会。

新增 EVE Ref 全量合同物品快照优先队列：先定位八种目标蓝图的合同，再用 ESI 核验物品。快照只决定检查顺序，不能直接产生提醒；未出现在快照中的新合同及其他候选仍按星域轮流检查。快照失败时自动使用常规队列，不把读取失败当作没有目标合同。单份物品请求失败会保留其他已完成结果，并把失败合同留在待核验队列；连续多次错误或限流时取消尚未开始的请求。

所有设置和投递状态写入 `data/monitor.sqlite`。不要把 `data/` 目录上传到公共仓库或网站；它包含本机授权后的加密刷新令牌。

## 云端复用旧项目

云端入口为 `cloud_run.py`，程序目录放入旧仓库的 `booster-monitor/`，将 `booster-monitor.yml` 放入 `.github/workflows/booster-monitor.yml`。它复用现有 `EVE_MAIL_API_KEY` Secret，向原 Cloudflare 通道提交邮件；不把密钥写入源代码、状态分支或日志，也不要求重新注册 EVE 应用。请勿同时启用本机和云端发信，否则两套独立记录可能导致重复提醒。

云端计划每 10 分钟触发，逐批核验 800 个新合同。手动触发可选择连续 10 轮（最多新增核验 8,000 个合同）；每轮保存进度，运行时间上限为 90 分钟。GitHub 调度可能延迟，ESI 也存在缓存，因此不能保证实时发现。首次完成全量核验可能需要多轮。云端设置修改 `cloud-config.json`；本机网页设置仅影响本机。默认关闭吉他交货限制，勾选后才只查吉他 4-4。远地合同尚未取得运输报价及玩家建筑取货权限，须在游戏中核对。

独立状态分支 `eve-booster-monitor-state` 保存公开合同物品、扫描进度和投递编号，不包含授权令牌。发信前必须成功提交“正在发送”状态，失败就停止投递；若发信后中断，下一轮将其视为结果待核对，避免重发。该分支与旧项目的 `results/` 分离。仓库是公开的，以上运行记录也公开可见。

发信前检查旧通道状态页的角色为 LadyGuaGua，并核对 MikeChong 的角色编号。旧通道只有一份角色授权，请不要在扫描时把它重新授权为其他角色。健康页面只证明保存了授权，真正可用仍须以游戏邮件接口返回投递编号为准。

## 真实限制

ESI 公开接口能读取合同及合同物品，但没有创建或接受合同的接口；游戏规则也不支持用求购合同要求交付蓝图拷贝。这个程序只负责发现、核验、估值和提醒，购买动作必须在游戏客户端里人工完成。

本版本是独立的药品制造利润监控，未合并旧项目的现货、通用蓝图估值规则。旧 Cloudflare 邮件服务 `eve-contract-opener.99617224.workers.dev` 已核实存在 LadyGuaGua 授权，但本机程序不会自动获得其密钥或授权。没有完成本机授权前，本机只能扫描和展示结果。云端通过旧项目的 Secret 使用邮件通道。

本版本同一合同成功发送一次后不再发送，没有实现旧项目的重复 TOP10 推送或累计次数规则。发信结果不确定时保留“结果待核对”；重新启动也不会自动重发。

## 数据与安全

- ESI 请求带应用标识 User-Agent，并遵守官方缓存和错误限流要求。
- 合同详情中的标题、物品名称、价格和链接视为不可信数据，邮件正文会转义 HTML 特殊字符。
- 读取到未知流程数、未知成品价格或材料卖单不足时，本轮不会把机会判为可提醒。
- 邮件 POST 发生超时或服务器错误时，状态记为“未确认”，不会自动重发；请先在游戏内核对。
