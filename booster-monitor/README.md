# 超强增效剂制造蓝图监控

独立的宁静服公开合同监控器，支持 Windows 本机界面和 GitHub Actions 云端运行。它与根目录的通用蓝图、现货和多件物品包扫描共用云端邮件服务，但估值、扫描进度和投递台账独立。

## 监控对象与流程

| 品种 | 制造蓝图类型编号 |
|---|---:|
| 蓝色药丸 | 25308 |
| 撞击感 | 25311 |
| 疯癫 | 25322 |
| 坠落感 | 25329 |
| 思维冲击 | 25511 |
| 梦呓 | 25512 |
| X—本能 | 25513 |
| 游离感 | 25539 |

这里监控以上八种**超强增效剂制造蓝图拷贝**，不是所有增效剂等级、任意制药反应配方或原始蓝图。

1. 默认读取 ESI 星域目录，逐星域读取公开合同的全部分页。允许高安、低安和 00 交货；开启 `jita_only` 后才只接受吉他 4-4。
2. 按合同类型、金额、到期时间和体积预筛。体积上限由实际蓝图体积与批次销量门槛推导，缺少体积时不猜测截断值。
3. 用 EVE Ref 合同物品快照定位目标蓝图，优先核验这些合同，其他待查合同按星域轮流推进。快照只决定顺序，不能直接产生提醒，也不排除快照中没有的新合同。
4. 从 ESI 读取物品，检查拷贝标志、数量与每张剩余流程。只接受全部物品均为同一种目标拷贝的物品交换出售合同；求购、拍卖、混装、原图和关键字段缺失不进入机会估值。
5. 对已取得有效物品记录的合同重算利润，筛选后检查投递台账。已核验物品可以复用缓存，不是每轮都重新联网读取全部旧合同。

某星域失败时记录覆盖不完整并保留进度；单份物品请求失败留待重查。多次错误或限流会取消尚未开始的请求。204、403、404 或空物品记录只暂存 30 分钟，之后重新核验；没有过期时间的旧空记录也会重查。

## 利润口径和默认门槛

配方使用仓库内的 [recipes.json](recipes.json)，运行时不会自动更新静态配方。`Planner` 向前展开反应与制造材料并按批次取整；气体等最终原材料按吉他足量卖单采购。成品参考价是伏尔戈星域最近可用完整交易日向前七天的成交量加权均价，**不是吉他可立即吃到的买单价格**。成交历史超过三天未更新或必要价格不可用时，不产生相应利润机会。

估算利润 = 成品参考收入 − 销售费用预留 − 蓝图合同总价 − 原材料采购成本 − 额外费用预留。

| 设置 | 默认值 |
|---|---:|
| 合同总价上限 | 20 亿 ISK |
| 每张最低剩余流程 | 50 |
| 每 50 流程最低利润 | 1 亿 ISK |
| 最低回报率 | 20% |
| 单批成品占七天成交量上限 | 25% |
| 销售费用预留 | 收入的 5% |
| 额外费用预留 | 每 50 流程 1000 万 ISK |
| 交货地点 | 默认不限定吉他 |

显示蓝图材料效率和时间效率，但成本展开未应用这些效率、建筑加成或角色技能。实际安装费、设施燃料、运输和改价费用由预留近似覆盖，没有取得逐份真实报价；一次性反应配方购置费也未单独估值。不能称为完整实际净利润，多个合同分别通过销量门槛，也不代表合计产量能同时售出。

本程序尚未接入通用扫描的 A1–D 风险标签、星门路线过滤或玩家建筑停靠权限验证；邮件主要显示星域与地点编号。远地取货条件须另行核对。

## 云端运行

入口为 [cloud_run.py](cloud_run.py)，工作流为 [药品制造蓝图监控](../.github/workflows/booster-monitor.yml)。

- 每小时第 3、13、23、33、43、53 分钟安排触发，通常每轮最多核验 800 个待查合同。GitHub 调度和 ESI 缓存可能延迟。
- 手动可选 1 或 10 轮。10 轮最多安排 8000 个待查合同，不保证实际成功数量，也不等于全市场检查完毕；运行超时上限 90 分钟。
- `dry_run` 只停止发信，仍读取数据并写入状态分支。命令行另有 `--limit`、`--rounds`，工作流固定传入每轮 800。
- [cloud-config.json](cloud-config.json) 覆盖 [core.py](core.py) 默认项；每品种的 `rules` 可在配置中覆盖。本机网页修改不影响云端。云端是否发信由 `--dry-run` 决定。
- 使用 GitHub Secret `EVE_MAIL_API_KEY` 调用既有 Cloudflare 服务，不读取本机授权文件，也不需要本机 Client ID。

## Windows 本机界面

在 `booster-monitor` 目录使用 Python 3.11 或更新版本：

```sh
python -m pip install -r requirements.txt
python app.py
```

打开 [本机界面](http://localhost:8787/)。网页依赖 Python 后端，不能只上传 `index.html` 作为静态网页使用。本机默认不开启邮件，通常每批最多查 160 个待查合同，完成后等待约 30 秒；错误时退避。

独立发信需注册 EVE 应用、填写 Client ID，回调为 `http://localhost:8787/oauth/callback`，只申请 `esi-mail.send_mail.v1`。在官方页面选择 LadyGuaGua，核验后保存授权并开启本机邮件。授权使用 PKCE，刷新令牌存入 Windows DPAPI 加密的 `data/mail-authorization.bin`；配置、缓存和投递记录在 `data/monitor.sqlite`。整个 `data/` 都不应上传公共仓库。

本机与云端台账独立，同时发信可能重复提醒。关闭网页不会停止后端，关机或休眠会停止本机监控。当前没有开机自启、自动安装或 PowerShell 启动器；应继续保留杀毒软件对历史启动脚本的隔离，不能凭当前源码认定旧查杀是误报。

## 投递与扫描进度

同一收件人的同一合同成功发送后不再重发；每封最多选取 10 个未投递机会，按每 50 流程利润排序。成功后约 30 分钟内不再发下一封。没有合格新合同时不发“暂无机会”邮件，也没有通用频道的榜单变化重发和累计推送次数功能。

云端 `eve-booster-monitor-state` 分支的 `state.json` 保存公开物品、扫描游标、机会、临时不可用期限和投递记录，不包含授权令牌。发信前必须成功保存“正在发送”检查点；结果不确定或进程中断时保留“待核对”状态，避免自动重复投递。失败记录不一定自动重试，应结合具体状态检查，不要通过删除台账排障。

| 字段 | 真实含义 |
|---|---|
| `regions_checked / regions_total` | 已尝试读取的星域数；失败详情另见 `region_errors` |
| `coverage_complete` | 星域列表是否全部成功读取，不代表全部物品核验完成 |
| `scanned / candidates` | 当前候选中已有核验记录的数量与总数，可能含缓存或临时不可用记录 |
| `new_inspected`、`item_errors` | 本轮取得物品/不可用结果的数量，以及物品请求错误数 |
| `pending` | 尚待核验数量 |
| `snapshot_target_contracts` | 快照定位目标数，不等于有效或达标数 |
| `opportunities` | 本轮数据及配置下达标的合同数，不等于本轮邮件数量 |
| `mail_error`、`delivery` | 邮件错误和投递台账；运行成功或健康页有授权不能替代具体投递编号 |

ESI 有效缓存会复用，合同仍可能已被接受；运行成功也可能伴随局部覆盖不足。应同时查看进度、错误、价格更新时间和合同状态。
